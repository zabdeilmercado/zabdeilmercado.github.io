Architecture case study / Mini-RAG

A local RAG pipeline where every answer can show its evidence.

The pipeline separates ingestion from questions, supports interchangeable retrieval backends, and keeps source passages visible for inspection.

Text ingest→Ollama embeddings→NumPy / pgvector→Top passages→Context-only answer
2 backendsMatching retrieval ranking
9 testsWorkflow and API coverage
3 passagesInspectable answer sources

Engineering focus

  • Source ingestion remains separate from read-time retrieval
  • Database questions never recreate tables or re-ingest documents
  • Same-origin local API with constrained text uploads

Honest limitation

Equivalent retrieval does not guarantee a correct generated answer. The project records this explicitly and treats answer-quality evaluation as future work.

Architecture case study / File Organizer

File cleanup designed around recovery, not deletion.

Every destructive-looking operation begins as a preview. Selected moves are quarantined and journaled so the application can inspect, reconcile, and restore them safely.

Folder scan→Exact duplicate groups→Review plan→Quarantine move→SQLite history / restore
0 dependenciesPython standard-library runtime
2 interfacesTk desktop app and CLI
Preview firstNo permanent-delete feature

Engineering focus

  • Exact duplicate detection with hard-link and reparse-point safeguards
  • Same-volume moves that never silently become copy/delete
  • Interrupted-operation reconciliation and conflict-safe restore

Safety boundary

Quarantine intentionally does not free disk space. Restore refuses to overwrite occupied paths or changed moved files, keeping ambiguous cases available for manual review.
